# EVRecharge India -- Mobile

The iOS and Android client for EVRecharge India. One shared Angular/TypeScript codebase (`src/`),
wrapped into two real native projects (`android/`, `ios/`) with [Capacitor](https://capacitorjs.com/).
It talks to the same backend APIs as the web app (`evrecharge-web`) at `https://evrechargeindia.com`.

## Why Capacitor instead of separate Swift/Kotlin apps

- One codebase to maintain, in the same language (TypeScript) the rest of this project already
  uses, instead of three parallel implementations (web, iOS, Android) drifting out of sync.
- Still produces genuine native app projects -- `android/` is a real Gradle/Kotlin project you open
  in Android Studio, `ios/` a real Xcode/Swift project -- not a webview-only wrapper with no native
  capability.
- The web app was already built mobile-responsive, so the UI carries over directly.

## Project layout

- `src/` -- the Angular app (routes, services, feature components)
- `www/` -- build output (git-ignored, regenerated by `npm run build`)
- `android/` -- native Android project (Gradle)
- `ios/` -- native iOS project (Xcode)
- `capacitor.config.ts` -- app id, name, and native webview settings

## Local development

```bash
npm install
npm run build              # builds the Angular app into www/
npx cap sync                # copies www/ into android/ and ios/, updates native deps
npx cap open android         # opens Android Studio
npx cap open ios             # opens Xcode (macOS only)
```

Whenever you change `src/`, re-run `npm run build && npx cap sync` before testing on a device or
simulator -- the native shells load a bundled copy of the web build, not a live server.

## CI

- `.github/workflows/build-android.yml` -- builds an unsigned debug APK on every push to `main`,
  uploaded as a workflow artifact (and optionally to a distribution host -- see below).
- `.github/workflows/build-ios.yml` -- builds for the iOS Simulator (unsigned) on every push, to
  catch native build breakage. It does not produce an installable device build (see below).

## What's automated vs. what needs your accounts

Everything above runs with no paid accounts. Getting onto a phone or into the stores needs steps
that only the account holder can do -- see `DEPLOYMENT.md` for the exact remaining steps and why
each one can't be automated away.
